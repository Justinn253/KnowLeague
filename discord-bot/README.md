# KnowLeague Discord Companion

This is the long-running Discord companion for the KnowLeague web app. It is intentionally a separate deployment from Next.js, while sharing the same Supabase project and the website's existing Discord profile-link identity.

## Current commands

- `/link` directs a Discord user to the existing KnowLeague profile-link flow.
- `/profile` confirms the caller's linked KnowLeague profile and links to its public page.
- `/help` opens a button-tabbed command guide with General, League, Fishing, and Collections categories; anyone can switch the shared panel’s visible category.
- `/rc` repeats the caller's most recent slash command with the same options for the current bot session. It continues to apply the command's normal member, permission, cooldown, balance, and channel checks.
- `/league skindle play`, `/league skindle guess skin`, and `/league skindle status` provide a test version of the UTC daily Skindle. `/play` posts a public activity card, while clue feedback and the final skin reveal stay private. Completion posts a spoiler-free public guess-count card with square markers. Test runs are held in bot memory and reset after a bot restart; they do not yet synchronize with website Skindle progress or global statistics.
- `/league account riot-id region` is a public snapshot test for the League Account Viewer. It opens the dedicated, non-indexed Discord render target at a 1,400px desktop viewport for the supplied `GameName#TagLine` and selected League region (including NA, EUW, EUNE, KR, JP, OCE, BR, LAN, LAS, TR, RU, PH, SG, TH, TW, and VN), then posts separate Overview, top-15 Mastery, and Current Game/last-six Match History PNGs plus an interactive-viewer link. Captures load the account once and render all three images from that result. They are serialized and draw two of the server's six screenshot-work units per minute, with a 30-second per-member cooldown, so browser and Riot lookup work remain bounded. Production uses the private Browserless service; local development can set `LEAGUE_ACCOUNT_VIEWER_CHROME_EXECUTABLE_PATH` when no remote browser endpoint is configured.
- `/league account-link riot-id region` privately stores one preferred Riot ID and League region for the calling Discord user. `/league account-mine` then uses that saved preference to run the same Account Viewer snapshot flow without asking for the account again. This is a bot-private convenience setting, not a Riot credential or a replacement for the website/Discord identity link.
- `/league champion champion section` posts the requested public Champion Catalogue image set from the local generated catalogue. `section` is required and offers **All sections** (eight images), **Overview**, **Statistics and playstyle**, **Ability details** (Passive, Q, W, E, R as five images), or **All skins**. It accepts canonical champion names, slugs, and supported search aliases, does not make a Riot API request, and includes a link to the interactive Champion Catalogue. Champion captures render only the requested panels and share the serialized Browserless queue, six-work-unit server budget, 30-second per-member cooldown, isolated browser context, 8 MiB per-image guard, and 20 MiB per-command attachment guard. All sections uses four work units, Ability details uses three, and each one-image section uses one.
- `/league randodraft mode teams player-N` drafts selected current server members in slot order. Any empty player slot before the last supplied player, or an entry that no longer resolves to a current human guild member, becomes a Wild Card with its own generated champion and build; trailing empty slots are not included. One team accepts 2–5 slots; two teams accept 2, 4, 6, 8, or 10 slots and assign the first half to Team 1 and the remainder to Team 2. It always uses **All build types are random**, posts one PNG generated by the website's **Copy image** export, then adds a public two-column text panel with each player’s champion and six items. Randodraft images share the browser capture queue, one capture-work unit, and 30-second per-member cooldown used by League Account Viewer and Champion Catalogue captures.
- `/league randodraft-vc mode teams [exclude-1] … [exclude-10]` uses eligible human members in the caller’s current voice channel. Exclusions are filtered before selection; it uses up to the first five members for one team or up to the first ten for two teams, dropping one final member only when needed to keep two teams even. It otherwise posts the identical Randodraft image and two-column item panel.
- `/xp view [member]` shows a member's level, total XP, segmented progress bar, and remaining XP. It defaults to the caller.
- `/xp add` grants a member XP and `/xp set-level` sets a member to a level; both are available only to members whose Discord role is selected in **Discord Configuration**.
- `/leaderboard [count]` posts the top active server members by XP, with 10 entries by default and up to 25 on request.
- `/invite leaderboard [user]` posts the top ten current inviters, or the current invite total for one Discord user.
- `/knowbucks balance [member]` shows your balance or a selected member's balance.
- `/knowbucks pay member amount` transfers KnowBucks to another non-bot server member.
- `/knowbucks coinflip amount` wagers KnowBucks on a cryptographically random 50/50 flip. A win returns twice the wager; a loss removes the wager.
- `/knowbucks leaderboard [count]` publicly shows the top active server members by KnowBucks, with 10 entries by default and up to 25 on request.
- `/knowbucks add`, `/knowbucks remove`, and `/knowbucks set` are available to members whose Discord role is selected in **Discord Configuration**.
- `/player stats [user]` shows a current member's chat and Fishing progression, KnowBucks balance, and an owner-controlled Skills tab. `/player inventory [user]` lists purchased player-shop equipment and active Bodyguard charges; additional inventory categories are planned for later player systems.
- `/player shop` has owner-controlled **Skills** and **Equipment** panels. It carries the existing Lucky, Haste, Cheapskate, and Money Mouser tiers out of Fishing, preserving every owned tier and its price progression. The Equipment panel sells Mask (100,000), Knife (250,000), Gun (1,000,000), Safe (250,000), and Bodyguard (1,000,000 KnowBucks for ten charges).
- `/rob user` targets a current non-bot server member. It has a one-hour Haste-reduced cooldown, starts at 5% success, and settles all money, cooldown, equipment, and Bodyguard charges atomically. Lucky, Knife, Gun, Safe, Mask, and Bodyguard behavior is shown in the Player Shop and Skills tab; a masked failed robber is revealed only when a defending Bodyguard catches them.
- `/snipe` costs 1,000 KnowBucks and publicly shows this channel's latest cached deleted message. Image attachments render as previews (up to three); non-image files remain links. It neither charges nor reveals anything when no eligible deleted message is cached.
- `/steal-emoji message-id` is available only to Discord administrators. It imports each external custom emoji found in a source message, including animated emoji where the server has an animated emoji slot. A raw message ID targets the current channel; an in-server copied message link can target another readable channel.
- `/steal-sticker message-id` is available only to Discord administrators. It imports each external sticker found in a source message. A raw message ID targets the current channel; an in-server copied message link can target another readable channel.
- `/temp update-leave-info` is a temporary administrator-only backfill for current human members. It stores their current join date, roles, and chat XP for leave panels. Invite attribution begins for new joins after deployment; the bot records last-message links going forward without storing message content.
- `/temp invite-tracker-status` is an administrator-only diagnostic for the current bot process. It reports the Manage Server permission, invite-cache age, and the reason the most recent join was attributed or left unknown.
- `/temp import-invite-leaderboard csv` accepts Invite Tracker's `/exportleaderboard invites` CSV and reconciles the existing calculated totals without double-counting a re-import. For exact historical retention, run `/temp import-invited-members inviter csv` once per inviter with that inviter's `/exportinvitedlist` CSV; current imported members are linked to their inviter so a later departure decrements the correct total.
- `/collections collection [member]` publicly displays your own or another current member's claimed skins, items, and runes one at a time with Previous and Next buttons. Each panel shows that collection's current daily upkeep; Show details includes sale and acquisition metadata.
- `/collections give member skin-id` transfers one claimed collection entry to a current server member by its four-digit KnowLeague ID.
- `/collections spawn [type]` immediately posts a skin, item, rune, or randomly selected type in the channel where the command was used. It requires a Discord role selected in **Discord Configuration > Collections**.
- `/collections summon` spends the configured KnowBucks cost (5,000 by default) to post a skin drop in the current channel. The summoner has the configured grace period to claim it first.
- `/collections capacity-add slots` buys collection space one slot at a time up to 50 total slots. The next slot costs 500 KnowBucks multiplied by its resulting slot number, while role-authorized staff can use `/collections capacity-force-add member slots` at no cost.
- `/collections steal` costs three times the claimed skin's configured sell value and applies a 30-minute cooldown after a paid attempt. `/collections favorite`, `/collections gamble`, `/collections search`, and `/collections sell` manage a collection by four-digit KnowLeague skin ID. Search results are catalogue previews only and cannot be claimed.
- `/collections upkeep-view` privately displays the current daily charge, a member's upkeep allocation and regular KnowBucks balance, any grace payment, and how many full daily charges the combined funds cover. `/collections upkeep-pay amount` permanently reserves up to 100,000 KnowBucks for upkeep; the allocation is spent first and cannot be withdrawn. Amounts beyond the remaining cap stay in the regular balance.
- `/fish expedition-set biome length [crew]` sends the first available, or selected unlocked, crew slot to one of seven biomes. Lengths are 5 seconds and one fish roll (level 0), 60 seconds and 12 rolls (level 10), 10 minutes and 120 rolls (level 20), and one hour and 720 rolls (level 30); crew trips take three times as long.
- `/fish expedition-progress` shows active expeditions and the most recent return. Completed expedition results include an owner-only **Fish again** button that relaunches the same biome, length, and crew slot after normal eligibility checks. `/fish shop` has public, owner-controlled category panels for KnowBucks fishing upgrades, while `/fish inventory` has focused Overview, Rods, Baits, Relics, Boats, and Titles tabs; rods and baits are equipped only from their respective tabs. Shared skills are bought from `/player shop`.
- `/fish help` provides the fishing-specific command and progression guide. `/fish chests-open` is a temporary, one-time-style legacy command that redeems every held migrated crate in one atomic result, while `/fish catalogue` tracks caught fish and found relics by biome. `/fish event-help` explains the active event and `/fish event-catalogue` tracks its event discoveries.

All non-administrative slash-command responses are public to the server, including profiles, XP, KnowBucks balances and payments, collection actions, coinflips, and snipes. `/collections upkeep-view` and `/collections upkeep-pay` are private because they expose the invoker's reserved and regular funds. XP/KnowBucks staff commands, `/steal-emoji`, `/steal-sticker`, and `/collections spawn` or `/collections capacity-force-add` remain ephemeral, including authorization failures and action results. Every command-channel denial is private to the invoking member and directly mentions the configured General, Fishing, or Collections destination channels. Collection-page button denials remain private to avoid channel spam. Leveling and skin claims observe eligible messages, reactions, and voice-state changes through the `Guilds`, `GuildMessages`, `GuildMessageReactions`, `GuildModeration`, `GuildVoiceStates`, and Message Content gateway intents. Message Content is enabled only because `/snipe` keeps a bounded in-memory cache (up to 5,000 recent messages for six hours, then the last deleted message in a channel for one hour), `/steal-emoji` and `/steal-sticker` read an administrator-selected source message, and the configured DISBOARD channel is inspected for a successful bump confirmation. Message text is never written to Supabase, and the bot neither receives nor records voice audio. The bot registers commands to one configured guild and ignores all events from every other guild.

## General command channel

KnowLeague administrators can select one or more optional default commands channels in **Profile > Discord Account > Discord Configuration > General**. The selection applies to `/help`, `/rc`, `/link`, `/profile`, `/xp`, `/leaderboard`, `/invite leaderboard`, `/knowbucks`, `/player`, and `/rob`; choosing **All channels** restores the default unrestricted behavior. `/snipe`, administrator-only commands, Fishing, Collections, and `/league` retain their own feature boundaries and do not inherit this setting.

The General tab can also select one optional website-Skindle results channel. When it is configured, a player who has linked their KnowLeague account to Discord gets their completed website Skindle result queued to the bot, which posts the same spoiler-free green/yellow/black grid format used by Discord Skindle. Unlinked players, guests, and servers with no selected sharing channel never create a post. The bot verifies that the profile still has the same Discord link immediately before posting.

## Member lifecycle and invite tracking

The General configuration tab can independently select an invite-tracker channel and template, a welcome-message channel and template, and a leave-panel channel. Join templates support `{user}`; invite templates also support `{inviter}` and `{inviteCount}`. The default welcome message links the three supplied server-information channels. The invite tracker compares Discord invite use counts and requires the bot’s **Manage Server** permission; it serializes attribution checks, waits for its ready-time invite cache, and retains verified short-lived deleted-invite state to reduce unknown sources. It also records observed one-use invite creation metadata and can use it as a fallback only when one pending invite is unambiguous. Irreducibly ambiguous or unavailable sources are still shown as unknown rather than guessed. Leave panels show the member mention, username, recorded join source, roles held at departure, server join time, chat XP level, and the last message link observed by the bot. If a leave-panel write fails, the configured leave channel receives a generic fallback panel instead of silently missing the departure; detailed errors remain only in server logs. Run `/temp update-leave-info` once after deployment to backfill current members’ join dates, roles, and XP. Discord does not provide a reliable complete server-wide “last message by member” lookup, so historical last-message links are retained when known and every new one is recorded after deployment.

## Chat leveling

Chat leveling is configured by KnowLeague website administrators from **Profile > Discord Account > Discord Configuration**. It starts enabled with 15 XP per eligible non-bot message and a five-second, per-member server-wide cooldown. The Lurkr-compatible total XP requirement for level `n` is `50n² - 100n + 150` (for example, level 10 requires 4,150 total XP).

Voice channel time also earns 1 XP for every completed minute. The bot starts a server-side session when a non-bot member joins a voice or stage channel, retains it when they move between channels, and atomically settles XP when they disconnect. It does not connect to calls, receive audio, or attempt to infer whether someone is speaking. A bot restart reconciles current voice states so stale sessions cannot later grant XP.

Administrators can pause leveling, adjust XP and cooldown values, configure a default announcement plus optional reward-level overrides, and select multiple Discord roles for each reward level. Announcement templates support `{user}` (a member mention), `{username}` (plain text with no ping), `{level}`, and `{xp}`. Leave the announcement channel ID empty to post in the channel where a member leveled up, or enter a text-channel ID to route every announcement there.

The leaderboard can optionally grant one dedicated champion role to the highest-XP eligible member. The bot checks it at startup, then on the first eligible human message after each hourly window; role changes can therefore take up to one hour after a lead changes. Members with selected exclusion roles are skipped when selecting the champion. Keep the champion role dedicated: it cannot be a level reward or manual-XP staff role.

When a member is banned while the bot is running, their existing chat XP is reset to zero and they are removed from champion-role consideration. Existing bans are not retroactively processed.

## KnowBucks

KnowBucks is the server currency that will support the future shop. Every level reached through automatic chat or voice XP grants `level × 1,000` KnowBucks. If one award crosses several levels, it grants the sum for every level crossed. Manual XP and level corrections intentionally do not mint KnowBucks.

Balances, level rewards, staff adjustments, payments, coinflips, snipes, and message rewards are atomic server-side transactions. The selected **Discord staff permissions** roles can add, remove, or set balances; remove never makes a balance negative. Members can publicly view balances and pay another non-bot server member, while staff adjustments stay private.

Every eligible human message has a 1% chance to grant a KnowBucks surprise: 75% of successful rolls award 1,000, 15% award 2,500, 5% award 5,000, 4% award 10,000, and 1% award 25,000. The bot uses cryptographically secure random rolls, persists only a successful reward's Discord message ID for idempotency, and announces the resulting balance in the channel.

In **Profile > Discord Configuration > General**, select the dedicated DISBOARD bump channel to enable reminders. In that channel only, KnowLeague waits for the final message state and treats `Bump done` or `bumped` text as a successful confirmation, then posts the exact next reminder time. It also reconciles the recent configured-channel history every 30 seconds, so a missed gateway event can be recovered. Optionally enter one Discord user ID there to receive a single channel reminder two hours after each successful bump. The pending reminder and a ledger of processed confirmation messages are persisted, so an edit, gateway reconnect, restart, or history reconciliation cannot produce duplicate reminders or confirmations.

## Fishing expeditions

Fishing is a server-authoritative expedition system. Harbor is free; the permanent Sail, Abiotic Turbine, Submersible Pod, Magic Conch Navigator, Drill Unit, and Radar Scanner unlock Warm Ocean, Hydroplant Reservoir, Sunken Sea, Kelp Forest, Crystaline Caverns, and Rallypoint Delta respectively. Each boat upgrade has both its listed chat-level and KnowBucks requirement. Boat upgrades are permanent and do not need equipping. Kelp Forest crate drops are Uncommon or Rare.

Every expedition saves its rod, one equipped bait, passive skills and relics, crew slot, private result seed, and active role/weekday modifiers before it starts. Plastic through God Rods progressively gate the eligible fish rarities; God Rod is already Mythic-ready, although the Mythic fish catalogue is intentionally empty for now. Base fish rarity weights are 1,000/200/50/10/0.1 for Common through Legendary, and every Legendary fish sells for 15 times its base value before other bonuses. Chum and Bloodworms can add matching-rarity fish, Magnet increases crate odds by 50%, Sonar halves fish-roll success while doubling relic odds, Mysterious Sea Food can add 50% more fish rolls, and Truffle Worm triples legendary odds while suppressing non-legendary fish. The four expedition lengths return 1, 12, 120, or 720 fish-roll opportunities respectively before bait and relic effects. New expeditions use 5.625, 67.5, 675, or 4,050 base Fishing XP before final whole-XP settlement rounding; crate XP is likewise 25% lower by rarity. Fishing level-ups award at least 500 KnowBucks, then 1.5 times the XP required by the reached level. Lengths 2 through 4 add 5%, 10%, or 15% to non-Common rarity weights. Completion results condense matching fish and automatically opened crate rewards into separate counted areas. Crew 1 requires level 40 and 100,000 KnowBucks, Crew 2 requires level 80, Crew 1, and 250,000 KnowBucks. Crew runs take three times as long with normal rewards. The Skills shop tab displays only the next unowned tier for each skill track.

The Halloween Fishing Event has ended. Its **Hellish Abyss** catches, Mythic **Cthulhu**, **Ghoulish Seafarer** title, and recorded event-catalogue data remain available for historical expedition settlement and player inventories, but newly launched expeditions no longer enter the event biome.

The bot uses one five-second reconciliation loop to settle due expeditions atomically and credit automatic fish and crate-item sales. Launches and progress views show a static estimated trip duration rather than Discord's relative timestamp, so a display cannot remain overdue while settlement is in progress. Completion replaces the original launch message with fish catches, separately listed opened crates, reward, resulting balance, and an owner-only repeat control; if that message was deleted, the bot posts a fallback result with the same control. Repeating starts a fresh expedition with the saved biome, length, and crew slot, but rechecks channel access, ownership, boat, level, and crew availability. The Fishing tab in Discord Configuration defaults `/fish` to all channels and can restrict it to selected synced channels. Shop, inventory, and catalogue controls expire after one minute of inactivity. A restart therefore cannot duplicate or lose an already-started trip.

Each fish-roll opportunity has a 0.01% base chance to find one permanent relic that the player does not yet own; Sonar and Conduit each double that chance. Relics are awarded atomically and marked prominently in the expedition result; their active descriptions are available from the Inventory Relics tab. Crate rates are one quarter of the prior chest rates: 5%, 2.5%, 1.25%, 0.25%, and 0.025% for Common through Legendary. Every caught crate immediately opens into one biome-specific item; its crate rarity sets the minimum loot rarity and all eligible rarities use 1000/200/50/10/1 weights. The Extra Crate Loot phenomenon gives each auto-opened crate a 50% chance to roll one additional item. Every listed item is valued from 0–30% above the average fish value for its biome and rarity, before sale bonuses. Migration 164 converts pre-existing generic chest IDs into legacy crates; `/fish chests-open` consumes all of those held crates atomically and is intended to be retired once that migration path is complete. Alongside the existing Sea Star, Alien Engine, Dual Hook, Rod Improvement Kit, Lost Pursasion Device, Conduit, Reservoir Growth, Giant Pearl, Magic Conch, Gemcracker, and Teleporter, the catalogue includes Lucky Coin, Streak Charm, Early Bird Bell, KnowLeague Lure, Harbor Dockhand's Ledger, Sunstone, Genesys Loop, Pearl Diver's Log, Tangle Net, Crystal Resonator, and Autopilot Relay. Genesys Loop repeats the same completed expedition preset at most twice before a manual refresh; Streak Charm and Early Bird Bell lock their history-dependent eligibility at launch. Gemcracker remains reserved for its future crate-loot balance update. The biome-filtered catalogue marks each player’s caught fish and found relics without relic descriptions; pets and storage remain held for later fishing updates. Shared skills remain active in Fishing after their purchase UI moves to `/player shop`.

## Collection drops

KnowLeague administrators configure skin drops and the collection economy in **Profile > Discord Account > Discord Configuration > Collections**. The drop-channel scope defaults to **All**, which includes every text channel where the bot can send messages; administrators can instead select up to 25 specific drop channels. The separate Collections command-channel scope also defaults to **All** and can select up to 100 channels for member-facing `/collections` commands. Once skin drops are enabled, the first eligible human message after the minimum interval posts a skin drop in that same channel. If chat remains quiet until the maximum interval, the bot posts a skin in a random eligible channel. Separately selected Collections admin roles can use `/collections spawn [type]` and `/collections capacity-force-add` in the invoking channel. A staff spawn may specifically select `skin`, `item`, or `rune`; omitting the type chooses one of those three types at random. Manual spawns, paid summons, and successful gambles preserve the one-live-drop rule without restarting the normal drop interval. The first human reaction to a live drop claims that collection entry; any emoji is accepted, and the claim window is configurable.

Skin drops draw from the generated 1,899-skin catalogue and use full splash art. Item drops draw from one highest-cost version of each actual, purchasable Data Dragon item name across every available historical snapshot and game-mode map where an icon is supplied. Enchantments, recalls, UI placeholders, and malformed localized names are excluded; Ornn Masterwork names are retained without their source icon token. Item rarities are Common below 1,000 total gold, Rare from 1,000–1,999, Epic from 2,000–2,999, Legendary from 3,000–3,999, and Mythic at 4,000 or more. The only no-price Mythic items are Kalista's Black Spear, Scarecrow Effigy, Poro-Snax, Head of Kha'Zix, Eye of the Herald, and Bonetooth Necklace. Rune drops use the generated Reforged-rune archive: sub-runes are Rare, keystones Epic, and rune styles Legendary. The existing Collections rarity-weight configuration applies to skins, items, and runes. Each drop type uses that same configured relative rarity weighting over its own available catalogue entries, and its card displays the resulting exact rarity chance. Every live or collected entry receives a unique active four-digit KnowLeague ID, and a catalogue entry cannot be held by more than one active collection. Stealing debits three times the configured sell price and starts a 30-minute cooldown only after a paid attempt; insufficient funds do not consume a cooldown. Drops, claims, capacity checks, KnowBucks changes, expirations, stealing, selling, and transfers are database-authoritative, so only one reaction can win and concurrent commands cannot exceed a member's collection capacity.

`npm run data:generate:discord-collections` refreshes the local item and rune catalogues plus `data/catalogs/discord-collection-item-tiers.md` and `data/catalogs/discord-collection-rune-tiers.md`, the rarity-labelled exports used for review.

## Local setup

1. In the Discord application already used by the website's `DISCORD_CLIENT_ID`, open **Bot** and add a bot user; copy the application ID and bot token. If website OAuth has not been configured yet, create one Discord application and use that same application for both OAuth and the bot. `DISCORD_APPLICATION_ID` must equal the website's `DISCORD_CLIENT_ID`.
2. In **Bot > Privileged Gateway Intents**, enable **Server Members Intent** and **Message Content Intent**. Server Members supports Collection cleanup and member lifecycle panels; Message Content supports the bounded `/snipe` cache, administrator `/steal-emoji` and `/steal-sticker` source parsing, and validated DISBOARD bump confirmations. This portal toggle is required in addition to the bot code; without it Discord can redact the successful bump confirmation. Leave **Presence Intent** disabled.
3. In **OAuth2 > URL Generator**, select `bot` and `applications.commands`, then select these **nine** bot permissions: **View Channels**, **Send Messages**, **Embed Links**, **Attach Files**, **Read Message History**, **Manage Messages**, **Manage Roles**, **Create Expressions**, and **Manage Server**. Manage Server is used only to read invite-use counts for join attribution. See [the Discord bot permissions guide](../docs/discord-bot-permissions.md) for the exact feature mapping, thread exception, role hierarchy rule, and the accepted **Manage Expressions** alternative. Do not grant Administrator.
4. Copy `discord-bot/.env.example` to `discord-bot/.env` and set each value. The bot loads this local file automatically when run from its workspace. Use the same Supabase project as the website. Keep `SUPABASE_SERVICE_ROLE_KEY` only in this local file or the bot host's secret manager. After the bot has synchronized the server channels, configure the DISBOARD bump channel and optional reminder user in the website’s **Profile > Discord Configuration > General** settings.
5. Add the same `DISCORD_GUILD_ID` to the website's `.env.local` (and its production environment) so the administrator-only settings page knows which server to configure.
6. Install dependencies from the repository root:

   ```bash
   npm install
   ```

7. Register the guild-scoped slash commands, then start the bot:

   ```bash
   npm run discord:commands:register
   npm run discord:dev
   ```

The website must have its existing Discord OAuth configuration (`DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, and callback URL) in place for account linking. The bot never stores Discord OAuth access tokens.

## Deployment

Deploy the website and bot as independent services from the same Git repository:

| Service | Build context | Build/start | Secrets |
| --- | --- | --- | --- |
| KnowLeague web | repository root | existing Next.js deployment | existing website environment variables |
| Discord bot | repository root, Dockerfile `discord-bot/Dockerfile` | Docker image command | values from `discord-bot/.env.example` |

For Railway, Render, Fly.io, or a container host, set the repository root as the Docker build context and point it to `discord-bot/Dockerfile`. Do not set the host's root directory to `discord-bot`, because the bot intentionally uses the root npm workspace and lockfile.

`KNOWLEAGUE_SITE_URL` must be the canonical public HTTPS website origin in production and must not contain URL credentials or point to a private/loopback host. Each `/league account` or `/league champion` screenshot run uses an isolated browser context, blocks non-canonical navigation plus known ad/telemetry hosts, bounds page/image waits, uses a small shared capture queue, disconnects the remote browser after two inactive minutes, and applies 8 MiB per-PNG plus 20 MiB per-command Discord upload guards. See [`docs/discord-snapshot-operations.md`](../docs/discord-snapshot-operations.md) for the operating and cost model.

For production, deploy Browserless as a separate Railway service in the same environment and set `LEAGUE_ACCOUNT_VIEWER_BROWSER_WS_ENDPOINT` on the bot to the Browserless service's `BROWSER_WS_ENDPOINT_PRIVATE` variable. The endpoint includes Browserless's private connection token and must remain a server-only Railway variable. When it is set, the bot connects to the remote browser and never launches a local Chromium process; it disconnects after two idle minutes or during shutdown without closing the shared Browserless service. The Browserless service receives only the public KnowLeague viewer URL and has no Discord, Supabase, or Riot credentials. Local development can omit the endpoint and use `LEAGUE_ACCOUNT_VIEWER_CHROME_EXECUTABLE_PATH` instead.

After changing `src/commands.ts`, run `npm run discord:commands:register` once with production bot credentials. Guild commands update quickly and do not require a website deployment. After applying migration 173, deploy the bot and register the revised command set; do not enable Message Content until the narrow retention policy above has been reviewed.

After applying fishing migrations 157 through 166, restart or redeploy the bot and register the revised command set:

```bash
npx supabase db push
npm run discord:commands:register
```

For a test bot, make sure `discord-bot/.env` contains that test application's `DISCORD_APPLICATION_ID`, token, and private-server `DISCORD_GUILD_ID`, then run the registration command from the repository root. Starting the bot alone does not create slash commands.

Build the container locally from the repository root with:

```bash
docker build -f discord-bot/Dockerfile -t knowleague-discord-bot .
```

The bot and website can be maintained on separate schedules. Restarting or redeploying the bot affects Discord commands only; it does not affect the website.
