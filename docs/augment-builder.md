# ARAM Mayhem Augment Community and Builder

League Tools exposes `/augment-builder`; that route opens the account-only community hub, while `/augment-builder/create` opens the editor. Drafts use a versioned browser localStorage key. The editor starts as a blank silver card with a silver icon; changing rarity clears incompatible artwork. Routine save messages are hidden, while storage failures remain visible. Authenticated publications appear in the community hub and the creator's public binder; guest publications remain viewable by direct link but are not listed in the account community feed. Owners can edit their published cards without changing the card ID, so existing votes remain attached to the design.

## Assets

Run `node scripts/generate-augment-catalog.mjs` to explicitly refresh the pinned local catalogue. Sources are CommunityDragon's extracted Riot assets across 77 patch snapshots from 13.14 through 16.18, combining Arena catalogue names with retained Arena and Mayhem icon directories. The catalogue contains 420 unique PNG images from 611 source IDs, including retained historical designs. A generated rarity and visual-order index limits the picker to matching artwork and places related names and similar silhouettes next to each other. Tinted glyphs are classified by their silver, gold or prismatic palettes; legacy illustrations without a known rarity remain available to old cards but are excluded from the picker. Display labels strip Cherry_/Name markers and split camel case. Silver icons additionally use reviewed labels and central-artwork groups in `data/catalogs/augment-silver-icon-groups.json`, so matching glyphs stay together even when their names differ. Run `node scripts/curate-silver-augment-icons.mjs` to apply these corrections locally without downloading or reclassifying artwork; enrichment and full generation also apply them. New silver assets follow the reviewed groups until curated. Gold icons use the same central-artwork curation with `data/catalogs/augment-gold-icon-groups.json` and the local-only `node scripts/curate-gold-augment-icons.mjs` command. Prismatic icons use `data/catalogs/augment-prismatic-icon-groups.json` and `node scripts/curate-prismatic-augment-icons.mjs`. Enrichment and full generation preserve all three sets of reviewed labels and groups; original labels remain searchable. Generation deduplicates decoded RGBA pixels (ignoring invisible RGB values), preserves alternate names for search, and maps removed IDs to canonical images so existing drafts and publications keep their artwork. Run `node scripts/enrich-augment-icons.mjs` to rebuild display metadata (legacy unclassified illustrations may consult the pinned source catalogue). Full catalogue generation runs both deduplication and enrichment. Run `node scripts/deduplicate-augment-icons.mjs` to deduplicate the local catalogue without downloading assets. Unreleased assets are excluded. Runtime uses only checked-in images, fonts, and icon metadata. Riot owns the artwork; CommunityDragon provides the extraction.

The canvas preview and clipboard/download PNG share one renderer and official Silver/Gold/Prismatic frames, backgrounds, Beaufort title and Spiegel body fonts. Inline stat symbols use the official League stat atlas and UV metadata. Stat formatting uses a small allowlisted text grammar: `[ap]text[/ap]`, `[health]text[/health]`, `[bold]text[/bold]`, `[icon:lethality]`, etc. Color formatting and inline icons have separate toolbars; formatting an empty selection inserts empty tags and places the cursor inside. The 20 official inline symbols include melee, ranged, level, attack speed, mana, critical strike, attack range, tenacity, life steal and magic penetration, using the existing atlas. Text and inline sprites share a vertically centered line axis in both previews and exported PNGs. Unknown tokens render literally; no arbitrary HTML is accepted. The card text is also exposed as accessible canvas alternative text.

## Database and API

Migration `134_augment_builder.sql` creates publications, separate account reaction and tier tables, and a bounded aggregate RPC. It must be applied before publishing, viewing binders, and voting can work. Migration `135_augment_extra_details.sql` adds separate quest requirements, restrictions and notes columns without altering legacy combined details, which the application reads as Notes. Migration `137_official_augment_ratings.sql` adds service-role-managed reactions and tier votes for checked-in official catalogue IDs. Browser drafts preserve disabled field contents; publishing includes quest/restriction text only when the corresponding toggle is enabled. Shared hover notes explain all four optional fields. Migration deployment is a separate operational step; creating the feature does not automatically push it.

All tables have RLS enabled and client grants revoked; only the server service role can access them. API routes validate inputs, derive account identity from bearer authentication, rate-limit publication/read/vote requests, and use aggregate-only telemetry. Repeated publication IDs are idempotent only for identical content and ownership. Authenticated owners can update their own card through the owner-checked edit endpoint. Unique vote keys guarantee one reaction and one tier per account and augment, with atomic upserts. Binders paginate 24 cards at a time and disclose no voter IDs. Owners can delete their cards, cascading related votes. Published designs and account binders are public, as disclosed before finishing.

Browser storage, clipboard, asset-loading, authentication, publication, missing-card, and empty-binder errors are surfaced. PNG download is available when image clipboard is unsupported. Saved draft data is validated before restoration.


## Editor and binder interactions

The description editor uses custom hover notes for every color and icon control. Optional-detail notes activate only from their info icon and have no click border. The builder preview keeps its public-sharing note above compact export controls. The community hub supports name search, newest and time-window popularity sorting, account-only card grids, and direct links to each augment. Its Official archive tab uses the checked-in data/catalogs/official-augments.json catalogue for current official effects, rarity, artwork, and source versions without runtime network requests; historical augments are intentionally excluded. Preview cards use concise in-game effects, resolve available numeric values, and translate allowlisted League stat markup into the same colors and inline icons as custom cards; regenerate it with npm run data:generate:augment-archive when the pinned source data is refreshed. Each archive card is a whole-card link to /augment-builder/official/[id], where users can inspect rarity and status, vote on community tier, react with likes or dislikes, and read the full source description. Official ratings use separate service-role-managed tables for the checked-in catalogue IDs. Binder pages show a spinner while loading and cache each loaded page in the browser session; cache entries are invalidated when a creator publishes, edits, or deletes an augment. Binder cards are full-item links with hover/focus treatment and bottom-aligned metadata. Publishing resets the builder draft to a new blank silver design, and owner edits are available from the public augment view. Community cards expose optimistic like/dislike controls, while public tier and reaction votes save in the background. Feed cards are cached for the current browser session and reused by public augment pages; edited cards invalidate those cached copies. Use augment as template seeds a fresh builder draft with the selected card content. Public augment and binder screens expose a To Community control; builder and hub controls retain history-aware behavior.
